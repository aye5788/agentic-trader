## 1. The candidate pipeline was doing work nobody could see

**Asked for:** *"each week on Friday it should be re-running the universe screen
that the agent selects stocks from; on a nightly basis it should be doing the
score re-ranking and showing the diff as part of the agent's morning intel."*

### 1a. The universe screen had never run — not rarely, never

`run_universe_refresh.sh` rescreens the 150-name pool the agent picks from. It
was armed 2026-07-20 as `0 19 1-7 1,4,7,10 *` plus a `date +%u == 7` guard in the
wrapper — the first Sunday of Jan/Apr/Jul/Oct. July had already passed when it
was armed, so its first real fire would have been **2026-10-04**. The candidate
pool sat frozen at its inception list while the docs described a maintained
universe.

Now **weekly, Fridays 17:00 ET** — after the close, before the 18:00 slow loop,
so the same evening's ranking already sees the fresh pool.

The cadence had been spelled in a cron field *and* a bash literal and stated
plainly in neither. It now lives in `[universe_maintenance] screen_day` and is
enforced by `universe_maint.screen_due()`, a pure selftested predicate the script
checks itself — so a wrong cron line cannot fire it on the wrong day. It fails
*toward running*, because a screen that silently stops is exactly what the last
month looked like.

It also had **no liveness check at all**, which is why nobody noticed. Added as
`health.SPECS["universe_refresh"]`, keyed to the proposal artifact rather than
the log, because a log moves even when the run does nothing.

⚠️ **The first weekly run will probably HOLD rather than auto-apply.** The
2026-07-28 dry run proposed 16 changes against an `auto_apply_max_changes` of 5.
After a month of drift that is correct behaviour: it phones and waits.

### 1b. The nightly re-rank was computed and thrown away

Rotation is weekly, so on five nights out of seven `hold_selection()` discarded
the fresh ranking entirely and nothing downstream ever saw it. The slow loop was
doing the work and deleting it.

`src/rank_history.py` (new) records each run to `research_store/ranks/`, and
`brief()` carries the diff into every session: top-20 entries and exits,
absolute-gate flips, biggest movers, and universe joins/leaves — which is how
Friday's screen shows up in Friday night's diff.

Verified on two real consecutive sessions (08-18 → 08-19): 80 names moved,
MRK/KO/MNST entered the top 20, **BAC and RTX — both held — fell out of it**, and
LIN/MDT/PLTR regained the absolute gate.

`diff()` is pure and distinguishes `no_snapshot` / `no_comparison` / `ok`, so a
first run can never render as "nothing changed". `--dry` records nothing.

⛔ **It rotates nothing.** The re-rank is a fact delivered to the session; what
it means is the agent's call.

### 1c. The agent was reading a different ranking from the book's

Found while explaining the above. **Two** divergences, one symptom:

- **The tilt was missing.** The slow loop ranks with the adopted 0.75
  sector-residual blend; `candidates()`/`universe()` called `momentum.compute()`
  bare. The agent's list was ranked on a different signal from the book's.
- **Funds were pooled in.** 18 index products were ranked alongside the 150
  single names. `score` is a PERCENTILE rank, so the pool *defines* it: a
  diversified basket carries structurally lower sigma, flatters itself on
  R/sigma, and shifts every single name's percentile.

`residual.kwargs_from_config()` is now the single source of the tilt, and
`screen.rank_book()` the single ranking. The selftest asserts behavioural
equality against the loop **and** that the tilt actually changes the order —
without the second assertion the first proves nothing.

## 2. The ETF sleeve is deleted, not disabled

**Asked for:** *"I want it gone like it was supposed to be two days ago when we
retired it."*

Retired 2026-08-16 by a config flag, positions sold 08-17 — and every piece of
machinery left standing: an `[etf_sleeve]` table, an 18-name universe file, a
second ranking engine in `select_book()`, **ETFs in the order-gate whitelist**,
ETFs pooled into the candidate screen, a `sleeve` field in the investor letter,
an empty SLEEVE table in the run report, and an "ETF sleeve" clause in the
charter the agent reads every session.

A retirement that leaves the mechanism in place is not a retirement. It reads as
live to every later reader — which is how a second model spent an audit
discussing an allocation that had been dead for four days.

**Deleted:** the file, the config table, the sleeve keys in `[portfolio]`, the
second engine, the ETF protective pass, `_all_tickers()` (zero callers), the
letter's always-false `sleeve` field, the SLEEVE report table, the charter
clauses. The backtests (`backtest.py`, `backtest_pit.py`, `sweep.py`) modelled a
70/30 two-engine book and now model the one that runs.

⚠️ **Their numbers are not comparable with anything published before today.**

**The whitelist is the part that bites.** `governance.whitelist()` was
`universe ∪ etf_sleeve`, and the config's stated reason for keeping the ETF half
was *"four are HELD right now"* — sold on 08-17, which voided the reason and left
the entry. It is the single-name universe alone now, so **a buy naming a fund is
refused**. A SELL is refused by nothing but the kill switch, unchanged: blocking
one would strip a position of its only protection.

### The hole that would have undone it

**Asked for:** *"check the screen the universe is built from to make sure it is
screening equities only."* It was not.

Weekly-screen ADDs come from moomoo's market-cap screen — documented as
UNFILTERED — falling back to `config/pit_pool.csv`, which `build_pool.py` had
been stuffing with all 18 funds. The only guard was a regex that `SPY`, `GLD` and
`XLK` all pass. An ADD is written into `config/universe.csv`, **which is the
order-gate whitelist** — so Friday could have put a fund straight back into the
tradeable universe and undone the deletion by another route.

Fixed in layers, the real one first:

1. **A positive test, not a denylist.** moomoo serves no `total_market_val` for a
   fund. The screen probes the actual add candidates and rejects anything without
   a market cap.
2. **A `NON_EQUITY` denylist backstop** — a denylist can only exclude the funds
   someone remembered to list.
3. **The filter lives in the ADD PATH**, not as a HOLD reason: a screen that
   merely flagged a fund would still have made it buyable the moment a human
   approved an otherwise routine proposal.
4. **The pond source cleaned** — `pit_pool.csv` 816 → 798.

### What was NOT deleted, and why the name changed

The residual tilt regresses every name on 11 sector return series to separate a
stock's own move from its sector's. Those are **factor inputs**: nothing can buy,
sell or hold them; they are not in the universe, the whitelist or the screen.

*"Fine then leave it but it shouldn't be using 'ETF', that muddies things."* —
correct, and calling a factor-model input an ETF is what let a deleted allocation
look alive. `SECTOR_ETFS` → **`SECTOR_FACTORS`**, and `fetch_prices` builds from
that constant plus SPY rather than a universe file.

Turning the tilt off remains a one-line signal decision (`residual_tilt = 0.0`),
the principal's to make — not a side effect of tidying.

## 3. Stops: two live defects, found the hard way

### 3a. An agent-set stop with no thesis was enforced by nothing

The monitor's watch set was `theses ∩ owned`, and theses are written by the
**nightly** slow loop — so any position opened intraday was unwatched for the
rest of that session however carefully the agent set its levels. `set_levels`
said so out loud and the position stayed unprotected anyway. It surfaced 08-19
(BAC, FTNT) and again 08-20 (JNJ, bought 10:40, stop 261.00 enforced by nothing).

An agent-set stop **is** a stop. `standalone_candidates()` + `arm_standalone()`
now watch an owned symbol on its own agent-set levels.

⛔ **The price guard is the whole safety argument.** On 2026-08-12 `set_levels`
accepted a stop *above* the live price and reported it enforced; an armed monitor
reads that as an instant breach and market-sells the entire position — a full
liquidation reached without any order being placed. So a candidate arms **only**
when a live price is known *and* strictly above the stop. Anything else is
refused with a reason, alarms, and stays flagged unprotected. Refusing costs a
position protection it did not have a moment ago; arming wrongly sells it at
market. Those are not symmetric. Mutation-tested.

Live within 2 seconds of the restart: `watching on agent-set stops (no thesis):
JNJ`; `unprotected` went `["JNJ"]` → `[]`.

### 3b. The exit executor could not record a sale it had already placed

11:52 ET, RTX breached its stop. The executor placed the market sell and **it
filled correctly** — order `6a8722dd…`, 0.026963 of 0.026963, $216.0601, one
execution, zero fees, verified at the broker. Exactly one RTX order exists for
the day. **The software stop did its job, and the 08-19 retry guard held**: one
launch, no duplicate sell.

It was then denied writing `research_store/monitor/exit_result.json` — the only
thing the monitor reads to learn a sale fired — by a blanket
`Edit(./research_store/monitor/**)` deny that also covers `Write`. Headless, it
stopped to ask for an approval nobody could give.

The deny was not wrong in spirit: that directory also holds `overrides.json` (the
enforced stops), `state.json` (fired flags) and `exit_request.json`. It was
written as a blanket and swallowed the one file the executor must write.

Permissions are now **per-file**, and every deny is stated for both `Edit` and
`Write` — narrowing one without the other would silently widen the other tool.

Reconciled from broker truth: result file written from the order record, snapshot
republished through `refresh_broker_snapshot()` (11 positions, RTX gone) rather
than hand-edited — the 2026-08-16 lesson.

## 4. The guards, because fixing an instance is not the job

A permission rule is only exercised on the path it guards, which is why 3b was
undiscoverable until real money was involved — the same shape as the allowlist
outage of 2026-07-30 and `check_settings_no_exec_wildcard` running nowhere that
mattered (2026-08-10).

**`repo_checks.check_exit_path_can_record`** (check 11) asserts statically, every
day, without needing a position to break: the exit path can write what the
monitor reads, and cannot touch enforced state. It models Claude Code's
deny-beats-allow precedence — the precedence that caused this — fails in **both**
directions, and fails on any `ask` rule, because an approval prompt in a headless
runner stalls *after* an order is placed. Mutation-tested against the pre-fix
settings.

**`health.unrecorded_fills`** was blind to the path that places the most urgent
orders in the system. It keyed only off `agent_decision`; a monitor-triggered
stop journals `exit_signal`, so RTX never entered the expected-a-fill set and the
one check whose job is *"an order executed and nobody wrote it down"* reported
clean while exactly that had happened. It now expects a fill for every **armed,
un-halted** `exit_signal` trigger. Alert-only and halted signals are excluded
deliberately: the monitor places nothing in those modes, and a check that cries
wolf on correct behaviour is how a real alarm gets ignored (issue #11, 08-18).

Verified against the real journal both ways: strip the RTX execution and it
returns `['RTX']`; with the fill recorded, nothing.

## 5. Two independent Codex audits, both DISSENT

Every finding was reproduced before being accepted. Some were real, some
overstated — recorded because the distinction matters.

**Audit 1** (`8cc77af`) — four real defects:

- **CRITICAL:** a held name the weekly screen drops from `universe.csv` got no
  protective thesis, therefore no stop. Latent while the universe never changed;
  the weekly screen made it reachable. *I had told the principal a held name
  keeps its stop. That was wrong, and it was the claim I reasoned about instead
  of testing.*
- Cooldown was applied by stripping names from the **scoring** universe, silently
  shifting every other name's percentile — and since the agent's screen has no
  cooldown notion, the two rankings diverged whenever one was active. Cooldown is
  now a selection rule; selection behaviour is unchanged and pinned.
- `--dry-run` wrote into the directory that had just become the liveness
  artifact, so a rehearsal could make a never-fired screen report green.
- NaN reached the rank snapshot as bare `NaN` (invalid JSON), and `bool(nan)` is
  `True` — a NaN eligibility flag would have read as *eligible*, an absolute gate
  failing open.

**Audit 2** (`a849d16`) — two real, two overstated:

- **Real:** my own comment said the equity probe "FAILS CLOSED" and it did not. A
  probe that threw or returned partial rows let unprobed candidates through on
  the name-shape regex alone. Also `cand` excluded incumbents while
  `propose_membership()` can re-add a dropped one, so a considered name was never
  probed. Now: probe the full add set; a failed or incomplete probe means **no
  adds at all** plus a forced HOLD.
- **Real:** stale strings — the newsletter prompt still explained the deleted
  `sleeve` field; `sweep.py`'s baseline markers still said `top-10`/`70/30`.
- **Overstated:** "whitelist bypass" rested on `require_whitelist=false` (live
  value is `true`, verified) and on `.claude/settings.json` having no order hook
   — the documented design since 2026-08-11, where the gate binds the loops and
  not interactive sessions.

## 6. Known, accepted, and stated rather than buried

- **Non-sector funds are no longer price-fetched** (IWM, EFA, EEM, GLD, TLT,
  AGG), so a manually-bought one would have no computable stop. Nothing in the
  system can buy them, none are held, and the case is loud: the slow loop prints
  `⛔ STILL UNPROTECTED` and the monitor writes `unprotected.json` every tick with
  health watching it. Fetching six fund series permanently to protect a position
  that can only arrive by hand is the wrong trade — but it is a judgement, so it
  is written down.
- **The slow loop can cause a sell**, in the sense that the monitor enforces the
  stop it supplies. That is the pre-existing stop mechanism and it is protection,
  not a mandate — but the distinction is stated rather than claimed away.
- **Backtest figures published before today are not comparable** with figures
  produced after it.
- **Intraday-opened positions were unprotected until the evening rebuild.** That
  is fixed for stops the agent sets (§3a). A position opened with *no* levels set
  is still unwatched until the nightly loop writes a thesis, and is reported
  unprotected throughout.
